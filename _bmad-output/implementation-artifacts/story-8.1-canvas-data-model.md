# Story 8.1 — Canvas Data Model

## Status: review

## Story

**As a** Developer,
**I want** a data model for positioned, connected artifacts on a spatial canvas,
**so that** the studio can render all workspace artifacts in a free-form layout.

## Acceptance Criteria

1. **Given** the canvas data model is implemented
   **When** an artifact is created
   **Then** it has position metadata (`{ x, y, width, height }`) and a type (`diagram | conversation | review | spec | story | note`)

2. **Given** two artifacts exist on the canvas
   **When** a connection is created between them
   **Then** the connection is persisted with source/target IDs and optional label

3. **Given** the V1 split-view layout
   **When** migrating to canvas
   **Then** existing artifacts are positioned automatically (conversation left, diagram right)

## Technical Notes

### Prisma models

Two new models added to `prisma/schema.prisma`:

**CanvasArtifact** — one row per artifact card on the canvas:

```prisma
model CanvasArtifact {
  id          String               @id @default(cuid())
  workspaceId String
  type        String               // "diagram" | "conversation" | "review" | "spec" | "story" | "note"
  refId       String?              // nullable FK to the underlying model (Diagram.id, Spec.id, etc.)
  x           Float                @default(0)
  y           Float                @default(0)
  width       Float                @default(480)
  height      Float                @default(360)
  zIndex      Int                  @default(0)
  title       String?
  createdAt   DateTime             @default(now())
  updatedAt   DateTime             @updatedAt
  workspace   Workspace            @relation(fields: [workspaceId], references: [id], onDelete: Cascade)
  outgoing    CanvasConnection[]   @relation("ConnectionSource")
  incoming    CanvasConnection[]   @relation("ConnectionTarget")
}
```

**CanvasConnection** — directed edge between two artifacts:

```prisma
model CanvasConnection {
  id        String         @id @default(cuid())
  sourceId  String
  targetId  String
  label     String?
  createdAt DateTime       @default(now())
  source    CanvasArtifact @relation("ConnectionSource", fields: [sourceId], references: [id], onDelete: Cascade)
  target    CanvasArtifact @relation("ConnectionTarget", fields: [targetId], references: [id], onDelete: Cascade)
}
```

`Workspace` model gets two new relations:

```prisma
  canvasArtifacts CanvasArtifact[]
```

### TypeScript types (client-side)

```ts
// src/lib/canvas/types.ts
export type ArtifactType = 'diagram' | 'conversation' | 'review' | 'spec' | 'story' | 'note';

export interface CanvasPosition {
  x: number;
  y: number;
  width: number;
  height: number;
}

export interface CanvasArtifact {
  id: string;
  workspaceId: string;
  type: ArtifactType;
  refId?: string | null;
  title?: string | null;
  zIndex: number;
  position: CanvasPosition;
}

export interface CanvasConnection {
  id: string;
  sourceId: string;
  targetId: string;
  label?: string | null;
}

export interface CanvasState {
  artifacts: CanvasArtifact[];
  connections: CanvasConnection[];
}
```

### Migration: V1 split-view → canvas

A seed/migration helper `src/lib/canvas/migrate-v1.ts` converts the existing V1 workspace layout to canvas positions:

- **conversation** artifact: `{ x: 40, y: 40, width: 480, height: 640 }`
- **diagram** artifact: `{ x: 560, y: 40, width: 720, height: 640 }`

This helper is called once per workspace on first canvas load (idempotent — skips if `CanvasArtifact` rows already exist for the workspace).

### API routes

- `GET /api/workspaces/[workspaceId]/canvas` — returns `{ artifacts, connections }` for the workspace
- `POST /api/workspaces/[workspaceId]/canvas/artifacts` — creates a new artifact (body: `{ type, refId?, x, y, width, height, title? }`)
- `PATCH /api/workspaces/[workspaceId]/canvas/artifacts/[artifactId]` — updates position/title/zIndex
- `POST /api/workspaces/[workspaceId]/canvas/connections` — creates a connection (`{ sourceId, targetId, label? }`)
- `DELETE /api/workspaces/[workspaceId]/canvas/connections/[connectionId]` — removes a connection

All routes protected by `requireAuth()`.

### No client-side rendering in this story

This story is purely the **data layer** (Prisma schema + migration + types + API routes). Canvas rendering is deferred to Story 8.2+.

## Dev Agent Record

### Implementation Plan

Implemented the full canvas data layer in 3 layers:

1. **Prisma Schema** (`prisma/schema.prisma`):
   - Added `CanvasArtifact` model: `id`, `workspaceId`, `type` (string), `refId` (nullable), `x/y/width/height` (Float), `zIndex` (Int), `title` (nullable), timestamps, `outgoing`/`incoming` relations to `CanvasConnection`.
   - Added `CanvasConnection` model: `id`, `sourceId`, `targetId`, `label` (nullable), `createdAt`, with cascade-delete FK relations to `CanvasArtifact`.
   - Added `canvasArtifacts CanvasArtifact[]` relation to `Workspace`.
   - Migration SQL committed at `prisma/migrations/20260303000001_canvas_data_model/migration.sql`.
   - Prisma client regenerated via `npx prisma generate`.

2. **TypeScript Layer** (`src/lib/canvas/`):
   - `types.ts`: `ArtifactType` union, `CanvasPosition`, `CanvasArtifact` (with `position` sub-object), `CanvasConnection`, `CanvasState`.
   - `migrate-v1.ts`: `migrateV1ToCanvas(workspaceId, options?)` — idempotent seeder that creates conversation (x=40) and diagram (x=560) artifacts at V1 split-view positions. Accepts optional `diagramId` to link via `refId`.

3. **API Routes** (all protected by `requireAuth()`, membership-verified):
   - `GET /canvas` — calls `migrateV1ToCanvas` on first load, then returns all artifacts (Prisma rows mapped to `{ position: {x,y,w,h} }` shape) + connections.
   - `POST /canvas/artifacts` — Zod-validated, creates artifact, returns 201.
   - `PATCH /canvas/artifacts/[artifactId]` — updates position/title/zIndex fields selectively.
   - `POST /canvas/connections` — verifies both source/target belong to workspace, creates connection.
   - `DELETE /canvas/connections/[connectionId]` — verifies ownership via source artifact, deletes, returns 204.
